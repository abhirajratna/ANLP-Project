- "tokens per step is a forward-pass count and does not depend on the GPU" holds for the fixed-k policies, but not for the adaptive ones (threshold, entropy-bounded, KLASS, C3a). - Suggested text: "...does not depend on the GPU for fixed-k policies; for adaptive policies it can shift slightly through fp16 rounding, which matching absorbs because it uses each configuration's report-half speed on one machine."
