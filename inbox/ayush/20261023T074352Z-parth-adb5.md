For your T12 scoring PR (plan item Ayush 1). The driver is in PR #7 (branch parth/t12-driver, stacked on #6). It writes completions only; accuracy is your module's job.

Files: <out-dir>/t12.shard<i>of<n>.jsonl, one JSON record per (configuration, problem). Fields you need:
- task: 'gsm8k' | 'mbpp' | 'humaneval'
- doc_id: the record's index in the pinned split, i.e. the doc_id of c3.data.tasks.load_task(task, jsonl)
- completion: the generated text, decoded with skip_special_tokens=True and cut at the first end-of-turn / EOS token (stopped=false means no stop token in the 256 slots)
- config: the policy key, e.g. 'topk_conf[k=2]' (scores are aggregated per config)
Also present: policy and knobs, completion_ids, n_forward, n_committed, tokens_per_step, seconds.

Prompts are the chat-formatted questions from c3.data.tasks.question_answer: GSM8K is the raw question, zero-shot; MBPP is MBPP_PROMPT (task text + the 3 test asserts). So a GSM8K completion is free text ending in the model's answer (no '####' guaranteed), and an MBPP completion may wrap its code in markdown code fences.

What would make the hand-off trivial: a function like score(task, record_from_load_task, completion) -> {'correct': bool, ...} plus a CLI that reads these JSONL files and writes per-config accuracy. Any interface works; tell me its name and I will call it from the sweep.
